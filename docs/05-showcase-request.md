# 쇼케이스(팔리는 화면) 요청법

Dribbble급 결과물이 필요할 때, "예쁘게 해주세요"는 아무것도 지시하지 않는다.
아래 6개를 채워서 요청하면 결과가 달라진다. (내가 만들 때도, 외주 줄 때도 동일)

## 요청 체크리스트

1. **도메인과 실제 콘텐츠를 문장으로**
   > HR 대시보드. 직원 42명, 부서 5개, 오늘 출근 38/결근 2/휴가 2. 이름은 한국식 3글자.

   이게 없으면 Acme와 Lorem이 나오고, 그 순간 목업으로 보인다.

2. **정보 블록의 개수와 종류를 열거**
   > KPI 4개 + 도넛(부서 분포) + 바(월별 채용) + 명단 6행 + 오늘 일정

3. **그래픽 자산 허용 범위** — 이게 없으면 회색 사각형이 나온다
   > 아이콘 Lucide, 아바타는 이니셜 원형, 일러스트·스톡사진 없음

4. **위계를 수치로**
   > 대표 숫자는 나머지 KPI의 2배 크기

5. **금지 사항** (브리프의 "가져오지 말 것"과 같은 원리)
   > 그라디언트 금지, 3D 금지, 라운드 8px 초과 금지

6. **레퍼런스는 "어디만 볼지"와 함께**
   > 이 샷에서 카드 간격과 도넛 스타일만. 색은 우리 스킨 그대로.

## 쇼케이스와 프로덕션은 다른 물건이다

| | 쇼케이스 목업 | 프로덕션 스펙 |
|---|---|---|
| 목적 | 문의·구매를 만든다 | 계약 후 안 깨지게 만든다 |
| 데이터 | 이상적, 3글자 이름, 4자리 숫자 | 40자 이름, ₩1,284,930,000, 500행 |
| 포함 | 아이콘·아바타·차트 풀 디테일 | 빈 상태 · 에러 · 로딩 · 모바일 |

둘을 섞으면 "샷은 예쁜데 실제론 다르다"는 클레임이 난다.
반대로 **둘 다 보여주면 차별화**가 된다 — 컨셉샷만 올리는 경쟁자와 갈라지는 지점.

## 완성도를 깎는 신호 (지금 화면에서 자가 점검)

- [ ] 회색 사각형/원이 아이콘 자리에 있다 → 미완성으로 읽힘. 최우선 교체
- [ ] 화면에 사람(아바타·이름)이 없다 → 온기 없음
- [ ] 차트가 한 종류다 → 시각적 리듬 없음. 영역+도넛+링+바 혼합
- [ ] 모든 카드가 같은 크기·같은 톤이다 → 시선이 흐를 곳이 없음
- [ ] 배지·진행률·상태점 같은 마이크로 디테일이 없다 → "꼼꼼함" 신호 부재

> 저장소의 풀 목업(`patterns/skins.mjs`의 `PREVIEW_FULL`)은 이 체크리스트를 통과하도록 만들어져 있다.
> 스킨 데이터만 바꾸면 아이콘·아바타·차트 4종이 전부 그 스킨으로 렌더된다.
