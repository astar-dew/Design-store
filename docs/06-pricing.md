# 가격 산정

금액은 전부 [`patterns/pricing.mjs`](../patterns/pricing.mjs) 한 파일에만 있다.
초기화면 **견적 탭**이 이 파일을 읽어 계산한다.

> ⚠️ 들어 있는 금액은 **조정해서 쓰는 출발값**이지 시장 표준가가 아니다.
> 본인 작업 단가나 실제 받아본 견적으로 바꿔서 쓸 것.

## 계산 구조

```
화면 소계   = Σ(화면 단가 × 수량)
기준액      = 화면 소계 × 스킨 난이도 계수
추가        = 기준액 × 옵션 비율   (다크모드 · 모바일 · 프로토타입 …)
합계        = 기준액 + 추가        (최소 진행 금액 미만이면 최소 금액)
```

옵션 비율은 **기준액에만 곱한다** — 옵션끼리 곱하지 않는다.
다크모드와 모바일을 같이 하면 서로 겹치는 작업이 있어서, 복리로 붙이면 과대 견적이 된다.

## 왜 화면 단위인가

외주 견적이 실제로 끊기는 단위가 화면이기 때문이다.
`03-outsourcing-brief.md`의 범위 표도 화면 단위이고, 패턴 카탈로그의 ID도 화면에 붙는다.
**패턴 선택(예: `list-toolbar` vs `list-filter`)은 가격에 반영하지 않는다** — 같은 화면의 다른 형태일 뿐이라
작업량 차이가 크지 않다. 작업량이 실제로 다른 것(에디터, 캔버스)은 별도 화면 항목으로 뒀다.

## 스킨 난이도 계수

같은 대시보드라도 스킨에 따라 작업량이 두 배 가까이 벌어진다.

| 계수 | 스킨 | 이유 |
|---|---|---|
| ×1.00 | `minimal-swiss` `neutral-saas` | 기본. 참고 사례가 많고 규칙이 단순 |
| ×1.15 | `editorial` `neo-brutalism` | 조판/보더 규칙을 전 컴포넌트에 일관 적용 |
| ×1.20~1.30 | `claymorphism` `data-dense` `aurora-gradient` | 섀도우 튜닝, 밀도 검증, 그라디언트 위 대비 |
| ×1.35~1.45 | `glass` `retro-y2k` `hand-drawn` | 화면마다 재검증·수작업이 필요 |
| ×1.90 | `spatial-3d` | 3D 에셋·카메라·성능 예산까지 설계 대상 |

## 다크모드는 추가금액

**기준액의 25~50%.** 스킨마다 다르다.

### 왜 비율이 스킨마다 다른가

다크모드는 "색 반전"이 아니라 **elevation 재설계 + 대비 재검수**다.
그래서 원래 스킨이 깊이를 어떻게 표현하느냐에 따라 작업량이 갈린다.

| 추가율 | 스킨 | 이유 |
|---|---|---|
| +25% | `minimal-swiss` `data-dense` | 색 수가 적어 매핑이 단순 |
| +30% | `neutral-saas` `neo-brutalism` | 이미 다크 기반이거나, 원색을 유지하고 보더만 반전 |
| +35% | `editorial` | 기본값 |
| +40% | `claymorphism` `hand-drawn` | 그림자 기반 깊이를 elevation으로 다시 설계 / 질감 에셋 대체 |
| +45% | `retro-y2k` `aurora-gradient` | 베벨 방향 전면 반전 / 그라디언트 재조색 |
| +50% | `glass` `spatial-3d` | 반투명·발광 위 대비가 화면마다 다시 깨짐 |

이 값들은 `pricing.mjs`의 `DARK.bySkin`에 있다.

### 포함

- 의미 토큰 다크 매핑 (배경·표면·텍스트·보더·상태색)
- elevation 단계 재설계 — 그림자 대신 표면 밝기로 깊이 표현
- 액센트·브랜드 색 다크 조정 (채도↓ 명도↑)
- 라이트/다크 양쪽 텍스트 대비 AA 검수
- 3상태 토글 UI (light / dark / system) 및 상태 유지
- 폼 컨트롤·스크롤바·placeholder·자동완성 배경
- 차트·데이터 시각화 팔레트 다크 세트

### 불포함 (별도 견적)

- 이미지·일러스트·3D 에셋의 다크 버전 제작
- 로고 다크 버전
- 마케팅 페이지 다크 (앱과 별개 스코프)
- 이메일 템플릿 다크
- 개발 구현 및 테마 전환 로직

> 이 포함/불포함 목록을 **브리프에 그대로 붙여라.**
> 다크모드가 재작업 1순위인 이유는 난이도가 아니라 *범위 합의가 없어서*다.
> "다크도 해주세요"가 이미지·로고·이메일까지 포함이라고 서로 다르게 이해한다.

## 그 외 옵션

| 옵션 | 비율 | 메모 |
|---|---|---|
| 모바일 반응형 | +45% | 벤토·스플릿·3단은 모바일에서 무너진다. 블록 순서를 새로 설계해야 함 |
| 태블릿 대응 | +20% | 모바일이 먼저. 태블릿만 하는 경우는 드묾 |
| 인터랙티브 프로토타입 | +15% | 개발 전달·사용자 테스트용 |
| 디자인 시스템 문서화 | +25% | 화면 10개 넘으면 이게 없을 때 개발 이식 비용이 더 든다 |
| 추가 수정 라운드 | +8%/회 | 기본 2회 외 |

## 단가 전제

이게 안 맞으면 금액도 안 맞는다. 견적서에 반드시 명시한다.

- 데스크톱 1440px 기준 화면 1개
- Figma 산출물 (오토레이아웃 · 컴포넌트화 · 토큰 바인딩)
- 시안 1차 + 수정 2회 포함
- 아이콘·일러스트·사진 신규 제작 불포함
- 개발 구현 불포함
- 표시 금액은 VAT 별도

## 거래 조건

- 최소 진행 금액 ₩2,000,000
- 1차 시안은 2화면(대시보드·목록)만 → **스타일 확정 후 나머지 확장**
- 계약금 50% / 잔금 50%

## 값 바꾸는 법

```js
// patterns/pricing.mjs
{ id: 'dashboard', name: '대시보드 홈', group: '핵심', price: 800_000 }  // ← 단가
SKIN_TIER['glass'] = { factor: 1.35, why: '...' }                        // ← 스킨 계수
DARK.bySkin['glass'] = 0.50                                              // ← 다크 추가율
TERMS.minimum = 2_000_000                                                // ← 최소 금액
```

고친 뒤 `scripts/build.sh` 하면 견적 탭에 바로 반영된다.
