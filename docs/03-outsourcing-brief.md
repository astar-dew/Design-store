# 외주 브리프 템플릿

레퍼런스만 던지면 100% 재작업이 난다. 레퍼런스는 **"어디를 보라"** 는 지시와 함께 줘야 한다.
아래를 그대로 복사해서 채운다.

---

## 0. 한 줄 요약
> (예) B2B 재고관리 웹앱의 대시보드·목록·상세 3개 화면을, Linear 톤의 뉴트럴 SaaS 스타일로.

## 1. 범위 (Scope)
디자인할 화면을 **개수로 명시**. 상태 화면을 빠뜨리지 말 것.

| # | 화면 | 데스크톱 | 모바일 | 비고 |
|---|---|---|---|---|
| 1 | 대시보드 홈 | O | O | |
| 2 | 목록 + 필터 | O | O | 행 500개 기준 |
| 3 | 상세(드로어) | O | O | |
| 4 | 빈 상태 3종 | O | - | 목록/검색결과/첫진입 |
| 5 | 에러·로딩 | O | - | 스켈레톤 포함 |

- 산출물: Figma 파일 (오토레이아웃 적용, 컴포넌트화, 라이트/다크)
- 미포함 명시: 아이콘 신규 제작 X, 일러스트 X, 개발 X

## 2. 스타일 지정 (분류 축으로)
`01-design-taxonomy.md` 의 값을 그대로 쓴다.
**형태는 패턴 카탈로그 ID로 지정한다** (`node scripts/build-patterns.mjs && open patterns.html`).
말로 설명하지 말고 ID를 적으면 해석 여지가 없어진다.

```
앱 셸:    shell-rail
사이드바: side-switcher
로그인:   auth-split
목록:     list-toolbar + list-drawer
상태:     state-empty / state-skeleton / state-error

스타일:   neutral-saas (보조: 미세 글래스는 오버레이에만)
레이아웃: app-shell + bento(대시보드 홈만)
밀도:     medium-high (테이블은 high)
컬러:     dark 기본 + light 대응 / 액센트 #___
타이포:   Inter, 헤드라인만 semibold
모션:     subtle (150~250ms, ease-out, 이동 8px 이내)
```

## 3. 레퍼런스 — "어디를 보라" 까지 적기

❌ 나쁜 예: "이런 느낌으로 해주세요" + 링크 5개
✅ 좋은 예:

| 레퍼런스 | **가져올 것** | **가져오지 말 것** |
|---|---|---|
| Linear 이슈 목록 | 행 높이·호버 상태·키보드 포커스 링 | 보라색 계열 컬러 |
| Stripe 대시보드 | 카드 간격과 KPI 타일 구성 | 일러스트 |
| 핀터레스트 보드 A | 컬러 팔레트·그래픽 질감만 | 레이아웃 일체 |

> 핀터레스트/드리블 레퍼런스에는 **"무드 참고용, 레이아웃은 따르지 말 것"** 을 반드시 명기.

## 4. 제약 조건 (Non-negotiables)
- 스페이싱 4pt 배수 / 라운드 값 3종 이내 / 폰트 사이즈 스케일 7단 이내
- 텍스트 대비 WCAG AA (본문 4.5:1) — 글래스·그라디언트 위 텍스트 특히
- 최소 지원 폭 1280px, 모바일 375px
- 실제 데이터 기준: 이름 최대 40자, 목록 500행, 숫자 통화 표기 ₩
- 사용 라이브러리: shadcn/ui 기반 (없는 컴포넌트만 신규 제안)

## 4-1. 다크모드 (추가금액)

다크모드는 별도 항목으로 견적한다. 기준액의 **25~50%**이고 스킨마다 다르다 —
산정 근거와 스킨별 비율은 [`06-pricing.md`](06-pricing.md) 참고.

**범위를 반드시 명시할 것.** 다크모드가 재작업 1순위인 이유는 난이도가 아니라 *범위 합의가 없어서*다.
「다크도 해주세요」를 이미지·로고·이메일 템플릿까지 포함으로 서로 다르게 이해한다.
`06-pricing.md`의 포함/불포함 목록을 그대로 붙여넣는다.

```
다크모드:  포함 (기준액 +35%)
  포함   — 토큰 매핑 / elevation 재설계 / 3상태 토글 / 폼·스크롤바 / 차트 팔레트
  불포함 — 이미지·일러스트 다크 버전 / 로고 다크 / 마케팅 페이지 / 이메일
```

## 5. 검수 기준 (이걸로 컨펌한다)
- [ ] 모든 인터랙티브 요소에 default/hover/active/focus/disabled 5상태 존재
- [ ] 빈 상태·로딩·에러 화면 포함
- [ ] 컴포넌트로 등록되어 있고 하드코딩 스타일 없음 (variables/styles 사용)
- [ ] 다크·라이트 양쪽 확인
- [ ] 긴 텍스트/많은 데이터 넣었을 때 안 깨짐
- [ ] 모바일 폭에서 bento 블록 순서가 의도대로

## 6. 일정 / 커뮤니케이션
- 1차 시안: 화면 2개(대시보드·목록)만 → 스타일 컨펌 후 나머지 확장
- 피드백 라운드: 2회 포함, 이후 추가 과금
- 채널: Figma 코멘트 (구두 피드백 금지 — 기록 안 남음)

## 자주 터지는 지점

1. **상태 화면 누락** → 개발 단계에서 급조됨. 범위에 처음부터 넣기.
2. **레이아웃을 컨셉샷에서 가져옴** → 실데이터에서 붕괴. 실제 제품(A그룹)에서만 가져오기.
3. **스타일 컨펌 없이 전 화면 진행** → 재작업 폭탄. 반드시 2화면에서 끊기.
4. **모바일 미정의** → bento/split이 모바일에서 무너짐. 블록 순서를 브리프에 지정.
5. **토큰 없이 하드코딩** → 개발 이식 비용 급증. 검수 기준에 명시.
