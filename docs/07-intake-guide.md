## 쇼핑몰 · 커머스

제품을 보여주고 결제까지 데려가는 화면. 인상의 8할은 상품 사진이 결정한다.

**첫 미팅에서 물어볼 것**

1. 상품 사진 퀄리티가 확보돼 있나? — 없으면 스킨보다 사진 계획이 먼저다
2. SKU 몇 개, 옵션(색·사이즈) 구조는? — 목록·상세의 밀도가 여기서 정해진다
3. 결제는 PG 위젯을 띄우나, 자체 플로우인가? — 체크아웃 화면 수가 갈린다
4. 프로모션·기획전 영역이 정기적으로 필요한가? — 운영 툴 범위에 영향

> ⚠️ 상품 사진이 약하면 어떤 스킨도 못 살린다. 사진 계획이 없으면 일러스트·타이포 중심으로 방향을 트는 게 낫다.

**관례 레이아웃** — 외주 지시에는 id 로 적는다

| 패턴 | 이름 | 왜 |
|---|---|---|
| `shell-topbar` | 탑바 전용 (사이드바 없음) | 쇼핑몰은 사이드바 없이 탑바 — 콘텐츠 폭이 상품 사진의 생명 |
| `list-cards` | 카드 그리드 | 제품 그리드. 비교가 필요하면 테이블 뷰 토글을 함께 |
| `detail-buybox` | 커머스 상세 (구매 박스 고정) | 제품 상세 — 이미지는 스크롤, 구매 박스는 고정 |
| `auth-social` | 소셜 우선 | 가입 마찰 최소화. 이메일은 구분선 아래로 |
| `form-wizard` | 위저드 (단계형) | 체크아웃 단계형 — 단계별 저장·복귀 필수 |

**어울리는 스킨**

| 스킨 | 이름 | 언제 |
|---|---|---|
| `sand-clay` | 샌드 클레이 | 따뜻한 소비자 톤 — 리테일·라이프스타일 |
| `ink-cream` | 잉크 크림 | 프리미엄·브랜드 커머스 — 제품 설명이 길고 읽히는 쪽이 중요할 때만 |
| `black-yellow` | 블랙 옐로우 | 스트리트·한정판 드롭 감성 |

**필수 화면** — 랜딩 · 목록 + 필터 · 상세 페이지 · 결제·체크아웃 · 로그인·가입 · 상태 화면 세트

화면 소계 **₩3,600,000** (스킨 계수·옵션 별도 — 견적 탭에서 같은 화면을 고르면 된다)

## 대시보드 · 어드민

매일 몇 시간씩 보는 운영 화면. 예쁨보다 스캔 속도가 제품이다.

**첫 미팅에서 물어볼 것**

1. 하루 몇 시간 띄워두는 화면인가? — 길수록 저채도·다크가 맞다
2. 목록 최대 행 수와 컬럼 수는? — 500행이면 밀도 설계가 달라진다
3. 권한 층위(관리자/운영자/뷰어)가 있나? — 같은 화면의 변형 수가 늘어난다
4. 야간 근무자가 있나? — 있으면 다크모드가 옵션이 아니라 필수

> ⚠️ 쇼케이스처럼 여백을 넓게 잡으면 실사용자 원성을 산다. 밀도는 사용 시간에 비례해 높인다.

**관례 레이아웃** — 외주 지시에는 id 로 적는다

| 패턴 | 이름 | 왜 |
|---|---|---|
| `shell-sidebar` | 사이드바 + 콘텐츠 | 메뉴 5~15개인 운영 툴의 기본값 |
| `dash-kpi` | KPI 행 + 차트 | 숫자를 매일 확인하는 홈 — 비교 기준(전주 대비) 필수 |
| `list-toolbar` | 상단 툴바 + 테이블 | 검색+필터칩+액션 한 줄. 벌크 선택 전환 설계 포함 |
| `form-settings` | 설정 (좌측 탭 + 섹션) | 좌측 탭 + 섹션 — 저장 버튼 위치 통일 |

**어울리는 스킨**

| 스킨 | 이름 | 언제 |
|---|---|---|
| `cobalt-gray` | 코발트 그레이 | 실패 확률이 가장 낮은 기본값 |
| `navy-signal` | 네이비 시그널 | 엔터프라이즈·물류 운영 톤 |
| `neon-engineering` | 네온 엔지니어링 | 모니터링·기술 조직용 |
| `blueprint` | 블루프린트 | 도면·설계 데이터를 다루는 사내 도구 — 선 굵기가 곧 정보 위계 |

**필수 화면** — 대시보드 홈 · 목록 + 필터 · 목록 + 상세(드로어) · 설정 · 상태 화면 세트

화면 소계 **₩2,850,000** (스킨 계수·옵션 별도 — 견적 탭에서 같은 화면을 고르면 된다)

## 콘텐츠 · 미디어

읽고 보고 듣는 서비스. 본문 조판이 곧 제품이다.

**첫 미팅에서 물어볼 것**

1. 텍스트 중심인가, 이미지·영상 중심인가? — 피드 형태가 갈린다
2. 체류 목표가 몰입(긴 글)인가 순환(짧은 소비)인가?
3. 구독·페이월이 있나? — 잠금 상태 화면이 추가된다
4. 작성자(에디터) 도구도 이번 범위인가? — 견적이 크게 달라진다

> ⚠️ 스킨 컨펌 전에 본문 조판(폰트·행간·본문 폭)부터 확정할 것. 콘텐츠 서비스는 그게 제품이다.

**관례 레이아웃** — 외주 지시에는 id 로 적는다

| `shell-topbar` | 탑바 전용 (사이드바 없음) | 독서 폭 확보 — 사이드바는 소음 |

**어울리는 스킨**

**필수 화면** — 랜딩 · 목록 + 필터 · 상세 페이지 · 로그인·가입 · 상태 화면 세트

## 예약 · 서비스

헬스케어·뷰티·클래스. 예약 플로우의 단계 수가 이탈률을 정한다.

**첫 미팅에서 물어볼 것**

1. 예약 단위가 무엇인가 — 시간? 인원? 기기? 담당자?
2. 노쇼·취소·변경 정책 화면이 필요한가?
3. 고객용만인가, 운영자(예약 관리) 화면까지인가?
4. 알림 채널은? (카카오 알림톡·SMS·이메일) — 상태 화면과 연동됨

> ⚠️ 예약 위저드가 3단계를 넘으면 단계마다 이탈이 는다. 화면 수를 세어 보여주고 합의할 것.

**관례 레이아웃** — 외주 지시에는 id 로 적는다

| 패턴 | 이름 | 왜 |
|---|---|---|
| `form-wizard` | 위저드 (단계형) | 날짜→시간→정보→확정. 단계별 저장 필수 |
| `auth-split` | 스플릿 (폼 / 비주얼) | 브랜드 신뢰를 주는 진입 |
| `list-drawer` | 목록 + 드로어 상세 | 운영자용 예약 목록 — 맥락 잃지 않는 상세 |
| `state-empty` | 빈 상태 | 예약 없음 상태가 신규 고객의 첫 화면이다 |

**어울리는 스킨**

| 스킨 | 이름 | 언제 |
|---|---|---|
| `mint-paper` | 민트 페이퍼 | 청결·신뢰 — 헬스케어 기본값 |
| `sand-clay` | 샌드 클레이 | 웰니스·뷰티 감성 |
| `cobalt-gray` | 코발트 그레이 | 운영자 화면용 |

**필수 화면** — 랜딩 · 온보딩 위저드 · 상세 페이지 · 알림 센터 · 상태 화면 세트

## 교육 · 클래스

강의·학습 서비스. 진도율과 수료 같은 "상태 표현"이 본체다.

**첫 미팅에서 물어볼 것**

1. 영상 강의인가, 텍스트·과제 중심인가? — 시청 화면의 형태가 갈린다
2. 진도·수료 체계가 있나? — 진행률·뱃지·수료증 화면이 추가된다
3. 결제 모델은? (단건 구매 / 구독 / 기업 계약) — 결제 화면 수가 달라진다
4. 강사(운영자) 도구도 이번 범위인가? — 콘텐츠 업로드·채점까지면 견적이 배로 뛴다

> ⚠️ 수강 전(빈 상태)·수강 중(진행률)·수료 후(완료) 세 상태가 다 달라야 한다. 상태 화면을 빼면 이 분야는 반쪽이다.

**관례 레이아웃** — 외주 지시에는 id 로 적는다

| 패턴 | 이름 | 왜 |
|---|---|---|
| `list-cards` | 카드 그리드 | 강의 카탈로그 — 썸네일·난이도·진행률 |
| `detail-article` | 아티클 (목차 고정) | 강의 시청·읽기 — 본문 + 커리큘럼 목차 고정 |
| `dash-kpi` | KPI 행 + 차트 | 학습 대시보드 — 진도율·연속 학습일 |
| `form-wizard` | 위저드 (단계형) | 수강 신청·결제 단계형 |

**어울리는 스킨**

| 스킨 | 이름 | 언제 |
|---|---|---|
| `indigo-class` | 인디고 클래스 | 교육 전용 — 진도·완료·잠김이 이미 구분되어 있다 |
| `mint-paper` | 민트 페이퍼 | 밝고 부담 없는 톤 — 키즈·취미 클래스 |
| `cobalt-gray` | 코발트 그레이 | 기업 교육·사내 LMS |

**필수 화면** — 랜딩 · 목록 + 필터 · 강의 수강 화면 · 커리큘럼·차시 관리 · 대시보드 홈 · 결제·체크아웃 · 상태 화면 세트

## 커뮤니티 · 소셜

피드와 글쓰기. 활동이 없어 보이면 죽은 서비스로 보인다 — 빈 상태 설계가 생사를 가른다.

**첫 미팅에서 물어볼 것**

1. 글 형식은? — 짧은 피드형인가, 포럼형 긴 글인가
2. 익명성 수준은? — 실명·닉네임·완전 익명에 따라 프로필 설계가 달라진다
3. 모더레이션(신고·차단·블라인드) 화면이 범위에 있나?
4. 알림 종류는? — 댓글·멘션·좋아요 각각 상태 화면과 연동된다

> ⚠️ 초기엔 콘텐츠가 없다. 시드 콘텐츠와 "첫 글 쓰기" 온보딩 프롬프트까지 디자인 범위에 넣어야 산다.

**관례 레이아웃** — 외주 지시에는 id 로 적는다

| 패턴 | 이름 | 왜 |
|---|---|---|
| `dash-feed` | 피드 + 사이드 | 세로 피드 — 위치 복원 처리 포함 |
| `shell-3col` | 3단 (목록 → 하위목록 → 상세) | 포럼형 — 게시판 → 글 목록 → 본문 |
| `form-single` | 단일 컬럼 | 글쓰기 — 완료율이 가장 높은 단일 컬럼 |
| `state-empty` | 빈 상태 | 초기 커뮤니티의 첫인상은 빈 상태다 |

**어울리는 스킨**

| 스킨 | 이름 | 언제 |
|---|---|---|
| `rose-lounge` | 로즈 라운지 | 커뮤니티 전용 — 아바타·투표·댓글 뎁스가 이미 잡혀 있다 |
| `oled-void` | OLED 보이드 | 미디어 소비형 — 야간 사용 많은 커뮤니티 |
| `black-yellow` | 블랙 옐로우 | 서브컬처·스트리트 감성 |

**필수 화면** — 목록 + 필터 · 게시글 + 댓글 스레드 · 생성·편집 폼 · 로그인·가입 · 알림 센터 · 상태 화면 세트

화면 소계 **₩2,600,000** (스킨 계수·옵션 별도 — 견적 탭에서 같은 화면을 고르면 된다)

## 금융 · 자산

숫자에 대한 신뢰가 전부인 화면. 표기 규칙이 스킨보다 먼저다.

**첫 미팅에서 물어볼 것**

1. 숫자 표기 규칙 — 원 단위 절삭? 소수점? 음수·하락의 색은?
2. 상승/하락 색 관례 — 한국은 상승=빨강. 글로벌 대상이면 반대다
3. 잔고 숨김(눈 아이콘) 기능이 필요한가?
4. 트레이딩 성격이 있나? — 있으면 다크모드가 사실상 필수

> ⚠️ 상태색 의미가 분야 관례와 충돌할 수 있다(빨강=상승 vs 위험). 색 의미표를 브리프에 반드시 명시.

**관례 레이아웃** — 외주 지시에는 id 로 적는다

| 패턴 | 이름 | 왜 |
|---|---|---|
| `shell-sidebar` | 사이드바 + 콘텐츠 | 계좌·상품·거래내역의 안정적 구조 |
| `dash-kpi` | KPI 행 + 차트 | 잔고·수익률 — 큰 숫자 위계 |

## 공공 · 기관

관공서·협회·대학·공기업. 예쁨이 아니라 "누구나 읽히는가"가 검수 기준이다.

**첫 미팅에서 물어볼 것**

1. 웹접근성 인증(KWCAG) 심사를 받나? — 받는다면 대비·초점·대체텍스트가 계약 조건이 된다
2. 주 사용자 연령대는? — 고령층 비중이 높으면 본문 크기와 터치 타깃을 키워야 한다
3. 전자정부 표준프레임워크를 쓰나? — 컴포넌트 선택에 제약이 생긴다
4. 민원 신청까지가 범위인가, 안내·공지까지인가? — 본인인증·폼 화면 수가 크게 달라진다

> ⚠️ 심미성 요청과 접근성 기준이 정면으로 충돌한다. 라운드를 키우거나 선을 얇게 하거나 회색 본문을 쓰자는 요청은 근거를 문서로 남기고 거절해야 인증 심사에서 되돌아오지 않는다.

## 브랜드 · 랜딩

회사·서비스 소개 페이지. 화면 수는 가장 적고 시안 반복은 가장 많은 유형이다.

**첫 미팅에서 물어볼 것**

1. 이 페이지의 목표 행동 하나는? (가입·문의·다운로드) — 하나로 못 좁히면 전환이 안 난다
2. 제품 스크린샷·영상 에셋이 준비돼 있나? — 없으면 목업 제작이 별도 비용이다

4. 유입 경로는? — 광고 유입이면 대부분 모바일이라 모바일 우선으로 짠다
